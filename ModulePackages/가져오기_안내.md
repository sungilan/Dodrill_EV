# DoDrill 모듈 패키지 가져오기 (2026-11-20, 2차)

패키지 2개와 이 안내가 한 세트다.

| 파일 | 내용 |
|---|---|
| `DoDrill_EV_Plugins_20261121.unitypackage` | **EV 수정본** FishNet · MasterServerToolkit · AutoHand. 모듈이 이 수정본 기준으로 만들어져서 정식판으로는 컴파일되지 않는다 |
| `DoDrill_Modules_20261121.unitypackage` | 모듈 폴더 9개(Common · Interaction · Avatar · Engine · Ui · Solo · Safety · Lobby · Setup) + 폴더 밖에서 쓰는 에셋 |

모듈 패키지에는 로비 UI가 쓰는 서드파티 `SimpleSpinner`와 `TrueShadow`(Le Tai's Asset, 유료 에셋)도 함께 들어 있다 — 내부 시험용이며 외부에 배포하지 말 것.

들어 있지 않은 것(직접 설치): Final IK(에셋스토어), DOTween, TextMeshPro, URP 설정, EV 콘텐츠(`Content`), 패키지 샘플(XR Hands 손 모델 등).

## 순서

1. **새 Unity 6000.3.x + URP 프로젝트**를 만든다. 서버 빌드도 할 거면 Unity Hub에서 그 에디터에 *Linux Dedicated Server Build Support*를 미리 설치한다(EV는 6000.3.10f1에 설치돼 있음).
2. **에셋스토어/외부 플러그인 설치**: Final IK, DOTween(설치 후 DOTween 설정 창에서 *Create ASMDEF*를 눌러도 되고, 안 눌러도 4단계가 만들어 준다).
   - **FishNet · MasterServerToolkit · AutoHand는 에셋스토어/깃허브 최신판을 설치하지 않는다.** EV 수정본이 필요하다(3단계).
3. `DoDrill_EV_Plugins_20261121.unitypackage`를 가져온다(Assets ▸ Import Package ▸ Custom Package, 전체 선택). 컴파일이 끝날 때까지 기다린다 — 이 시점에는 오류가 나도 정상이다.
4. `DoDrill_Modules_20261121.unitypackage`를 가져온다.
   - 가져오면 `Setup` 모듈(`DoDrillSetup`)이 자동으로 한다: ① Final IK에 `RootMotion` asmdef 만들기(에셋스토어판에는 없어서 이게 없으면 `RootMotion`·`VRIK`·`FingerRig`를 못 찾는다) ② DOTween에 `DOTween.Modules` asmdef 만들기(없으면 `DOFade`·`DOAnchorPos`를 못 찾는다) ③ 태그 `HoldPoint`·`Anchor` 추가 ④ 없는 필수 패키지 목록을 보여 주고 설치 여부를 묻는다 → **설치**를 누른다(Unity가 잠시 멈추고 다시 컴파일한다).
   - 창이 안 뜨거나 놓쳤으면 메뉴 `Tools ▸ DoDrill ▸ 가져오기 설정(asmdef·태그·패키지)`을 실행한다.
   - 서버를 Windows에서 Linux로 빌드하려면 같은 메뉴를 한 번 더 실행해 Linux 툴체인 2종 설치를 선택한다.
5. 컴파일이 끝나면 콘솔 오류가 없어야 한다. 남아 있으면 Unity를 껐다 켜고 `Assets ▸ Reimport All`을 한다.
   - 새 프로젝트에서 TMP 기본 리소스 안내가 뜨면 `Window ▸ TextMeshPro ▸ Import TMP Essential Resources`.
6. 메뉴로 시작한다.
   - `Tools ▸ DoDrill ▸ Localization 설치`
   - `Tools ▸ DoDrill ▸ 로비 템플릿 씬 설치` → `Assets/Scenes/Lobby/`에 Client·Master·Room·Spawner 씬이 생긴다. `Client.unity`를 열고 Play하면 로그인 화면이 뜬다(마스터가 없으면 "연결 중"에서 재접속을 반복하는 게 정상).
   - 범용 프리팹·멀티플레이 예제는 `Assets/99_ModuleExample`에 있고 패키지에는 없다(필요하면 EV에서 따로 가져온다).
7. **서버 빌드**: `Tools ▸ DoDrill ▸ 로비 빌드 프로필` → `서버 둘 다 빌드`(룸 → 마스터). 빌드 전에 창에서
   - `룸 서버 실행 경로` = 서버(컨테이너) 안에서의 룸 서버 파일 경로. EV 도커 구조면 `/home/RoomServer/RoomServer.x86_64`
   - `스포너 machineIp` = 클라이언트가 접속할 서버 주소
   를 적는다. 결과는 출력 폴더의 `MasterServer/`, `RoomServer/`.
8. **서버 올리기(EV 방식 = NAS 도커)**: NAS의 `docker/Ubuntu/` 아래 **새 폴더**를 만들어 `MasterServer/` 안 파일을 폴더 바로 아래에, `RoomServer/` 안 파일을 그 안 `RoomServer/`에 올리고 `start.sh`를 복사한다. 새 컨테이너(같은 이미지·포트, 볼륨만 새 폴더)로 실행한다. **EV 서버 폴더·컨테이너를 덮어쓰지 말 것** — 포트가 겹치므로 시험하는 동안 EV 컨테이너는 멈춘다.
9. 클라이언트 `Client.unity`의 `ClientToMasterConnector.serverIp`를 서버 주소로 바꾸고 Play → 게스트 → 방 만들기 → 준비 → 시작.

## 확인된 것 / 확인하지 못한 것

- 확인: 빈 프로젝트와 별도 테스트 프로젝트에서 위 순서로 컴파일 오류 0, 로비 화면 표시.
- 미확인: 서버 빌드 실행, 방 시작(룸 서버 기동·게임 씬 진입), 2명 이상 접속, VR·모바일 실기기. Windows 서버 빌드는 셰이더 변형 준비가 수십 분 이상 걸려 시험을 중단했다(Linux Dedicated Server 사용).
- `Setup` 모듈의 자동 설정(asmdef·태그·패키지 설치)은 새 프로젝트에서 처음 실행해 보는 것이다. 문제가 생기면 수동 방법: Final IK `Plugins/RootMotion`에 이름이 `RootMotion`인 asmdef(참조 `Unity.InputSystem`)와 `Editor/`에 `RootMotionEditor`(참조 `RootMotion`, Editor 전용), DOTween `Modules` 폴더에 `DOTween.Modules`(참조 `UnityEngine.UI`·`Unity.TextMeshPro`, overrideReferences, precompiled `DOTween.dll`).

## 알아둘 점

- `ModulePackages` 폴더는 용량이 커서 git에 올리지 않는 것을 권한다.
- 패키지에는 EV 문구가 든 `UI_Text` 테이블이 들어 있다(로비·공용 UI가 같은 테이블을 쓴다).
- 템플릿 씬의 서버 주소 기본값은 `127.0.0.1`이다.
- 자세한 내용은 `Assets/01_Script/README.md`와 각 모듈 폴더의 `README.md`.
